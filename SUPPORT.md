# Help and feedback

Start with the [first-annotation guide](docs/getting-started.md),
[example catalog](examples/README.md), and [troubleshooting](docs/troubleshooting.md).
The [compatibility matrix](docs/compatibility.md) describes tested environments.

## Report a problem

[Open an issue](https://github.com/Ponchia/bronto-annotations/issues/new/choose)
with a minimal reproduction. Include the installed package version, host library
and browser versions, expected and actual behavior, and the smallest annotation
inputs that reproduce it. For layout problems, include bounds, note sizes,
obstacles, and any zoom or coordinate transform. A screenshot helps explain a
visual problem, but runnable input makes it possible to fix it.

Remove credentials, customer information, and private application data before
posting. Report security vulnerabilities privately using [SECURITY.md](SECURITY.md).

## Ask an integration question

Describe what you already render and which part you want to annotate. Mention
whether the annotation is static, editable, or regenerated after data changes.
A small public example is more useful than a complete application dump.

Check the [release notes](https://github.com/Ponchia/bronto-annotations/releases)
when examples from `main` differ from an installed npm release. Maintainer
availability varies; there is no promised response time or commercial support
agreement attached to the open-source package.

## Share a real integration

An issue describing what worked, what needed configuration, and where the
public guide was unclear is welcome. Include a public link only when you have
permission to share it. Do not disclose private downstream applications.

Contributions are described in [CONTRIBUTING.md](CONTRIBUTING.md). Optional
financial support is described separately in [FUNDING.md](FUNDING.md).
